# CHANGELOG 상세 로그 — LiteRT-LM Studio

(325/325+lint 신규 0, PR #13)

* 릴리스 게이트 (T-370): `release.yml`에 unit 테스트 스텝을 넣고, 태그와 `MARKETING_VERSION`이 다르면 DMG 발행 전에 실패하게 했다. [macos]

* 안정화 S2 (T-371): 앱 시작 중 종료될 때 남는 고아 데몬을 인자 기준으로 판정하고 폴링을 조기 탈출시켰다. `ConfigStore` 백업은 원자 쓰기로 바꾸고, 다운로드 `.part` 크기는 Int64로 단일화했다. [macos]

* 문서·문구 정정 (T-373): 사용설명서 기준 버전을 0.7.152로 올리고, 스테이징 폴더 도움말·주석을 앱 데이터 홈(`~/.litert-lm-studio/`) 기준으로 고쳤다. [macos]

* 화면 문구 전환 (T-363): 앱이 그리는 모든 UI 문구를 `L(L10n.…)` 키 참조로 바꿔 한국어/영어가 즉시 전환되게 했다. 설정의 MCP·스킬 탭, 웰컴·정보·명령 팔레트, 모델 카탈로그와 가져오기 시트, 시스템 모니터, 디버그 패널, 메뉴바 팝오버, 단축어 허용 목록, 창 제목과 앱 메뉴(새 채팅·서버·보기), 마크다운 코드 복사까지 포함한다. 창 제목과 앱 메뉴는 SwiftUI가 1회 구성하는 표면이라 다음 실행 때 반영된다. [macos]

* 표시 문구 키 전환 (T-362): 문자열을 만들던 순수 로직(도구 카탈로그·모델 카탈로그·모델 별칭·세션 정렬·
  벤치마크 단계/상태/보관 개수·상태 한 줄·메뉴바 상태/동작·인스펙터 요약·상대 시간)을 `L10n` 키 기반으로
  바꿔 언어를 인자로 받지 않고도 즉시 전환되게 했다. 도구 이름·설명은 `tools.<name>.title|detail` 키를
  이름에서 파생시켜 20종을 일괄 처리하고, 모델 모달리티는 `ModelAlias.modalities(_:)`로 정리했다.
  벤치마크 "전체 기록" 필터는 표시 문구와 저장 값을 분리(`allModelsToken`)해 언어가 바뀌어도 필터가
  유지된다. 테스트는 시스템 언어와 무관하게 결정적이도록 `LiteRTLMStudioTestCase`에서 한국어로 고정하고,
  영어 전환·포맷 인자·전 키 해석을 검증하는 커버리지 테스트를 보강했다(318/318). [macos]

* 다국어 인프라 (T-361): 설정 > 일반 > 외관에 언어 항목(시스템/한국어/English, 기본 시스템)을 넣고
  앱 내부 문구를 다시 시작 없이 바로 바꿀 수 있게 했다. 번역은 `Localizable.xcstrings`(String Catalog,
  소스 언어 한국어)에 모으고 `L10n` 시맨틱 키로만 참조한다. 앱이 직접 그리는 UI는 즉시 바뀌고, 권한
  대화상자처럼 macOS가 그리는 문구는 다음 실행 때 반영되도록 `AppleLanguages`도 함께 기록한다. ko/en 키
  누락과 미번역을 잡는 커버리지 테스트를 추가했다. [macos]

* 경고 정리 (T-360): 동작 변경 없이 린트·컴파일러 경고를 정리했다. swiftlint 11건은 파일/함수를
  새 파일이나 헬퍼로 분리해 0으로 만들었고(`ToolCallFormat` 분리, 후속질문 뷰 3종 분리, 벤치마크
  확장 분리, `streamEvents`·`request`·`runServerTurns` 분해, `JSONObjectScanner`·`CachedBackends`
  도입), 헤더맵 경고는 `ALWAYS_SEARCH_USER_PATHS=NO`로 없앴다. 앱 코드 경고 2건도 정리했다
  (`FollowGate.find`의 `superview` 접근은 `MainActor.assumeIsolated`, `DaemonManager.port`는
  `nonisolated`). 벤더 소스(`Core/LiteRTLM`)의 Sendable 경고 2건은 정책상 그대로 둔다. [macos]

* 설정 탭 재구성 (T-359): 탭별 분류를 감사해 잘못 놓인 항목을 옮겼다. `웹 도구 사용`은 채팅 탭에서
  도구 탭의 웹 섹션(Exa 키·테스트)으로, `대화 기록 전송`은 일반 탭에서 채팅 탭으로, `첫터치 프리필`은
  일반 탭 시스템 섹션으로, `벤치마크 기록 보관`은 일반 탭 고급 섹션으로 이동했다. 채팅 탭에는 표시·동작
  섹션 헤더와 함께 채팅 글자 크기 슬라이더와 세션 정렬을 새로 넣었고, 도구 탭 작업폴더는 파일·셸 섹션으로
  묶었다. 또 설정 탭에 중복으로 있던 MTP 토글과 적용 버튼을 제거하고 엔진 설정을 인스펙터로 일원화해,
  설정 창을 열 때 인스펙터의 미저장 변경이 취소되던 문제도 없앴다. [macos]

* 설정 창 좌우 여백 근본 수정 (T-358): T-357 이후에도 좌우가 상하보다 크게 보인 원인은 패딩이 아니라
  창 크기였다. `Settings` 씬은 `defaultSize`가 없어 macOS 기본 900×508로 뜨는데 내용 최소 폭은 560이라,
  grouped `Form`이 행을 가운데 정렬된 열로 배치하며 좌우에 약 170pt씩 잉여 여백이 생겼다. 내용 폭을
  600으로 고정(`minWidth/maxWidth`)하고 `Settings` 씬에 `.windowResizability(.contentSize)`를 붙여
  리사이즈를 잠갔다. 여백은 `dsSettingsForm()`을 사방 균일 `.padding(DSSpace.l)`로 되돌려 좌우·상하를
  맞췄고, 저장돼 있던 900pt 프레임 키를 1회 삭제했다. 설정 창 제목이 선택된 탭 이름(일반/채팅/…)으로
  표시되던 문제도 함께 고쳐, 창 제목을 "설정"으로 고정했다(SwiftUI가 다시 덮어쓰므로 창 `title`을 KVO로
  감시해 재설정). [macos]

* 설정 창 좌우 여백 정리 (T-357): 5개 탭이 `.formStyle(.grouped)` 위에 균일 `.padding()`을 더해
  좌우가 상하의 약 두 배로 벌어져 있었다. 좌우는 grouped 폼의 네이티브 섹션 인셋에 맡기고 세로
  여백만 주는 공용 모디파이어 `View.dsSettingsForm()`(Components.swift)으로 통일했다. 설정 창
  최소 폭도 580 → 560으로 줄였다. [macos]

* 설정 창 탭 깜빡임 수정 (T-356): 일반·채팅·도구 탭이 `Form(.grouped)`을 `ScrollView`로 한 번 더
  감싸 스크롤 뷰가 중첩돼 있었다(T-320의 잘림 대응). 탭 바에 마우스를 올리면 `NSTabView` 재레이아웃
  때마다 안쪽 스크롤이 다시 측정돼 탭 영역이 깜빡였다. 바깥 `ScrollView`와 잉여
  `.padding(.bottom, 32)`를 제거해 MCP·스킬 탭과 같은 `Form(.grouped).padding()` 구조로 통일했다.
  `Form(.grouped)`가 자체 스크롤하므로 잘림 없이 5탭이 동일하게 동작한다. [macos]

* 메뉴바를 Etchost식 수동 상태 아이템+팝오버로 전환 (T-355): `MenuBarExtra(.menu)`(텍스트 메뉴)를
  `NSStatusItem`+`NSPopover`로 교체. 메뉴바 아이콘은 기존 칩+상태 점 라벨을 그대로 호스팅하고,
  클릭하면 아이콘 아래에 상태 카드(데몬 상태·`:9379`·가동 시간·현재 모델)와 빠른 동작(서버
  시작/중지·새 채팅·최근 채팅방 3개·메인 창 열기·모델 관리·설정·종료)을 담은 팝오버를 띄운다.
  팝오버는 씬 밖이라 `openWindow` 환경을 쓸 수 없어 `.openMainWindow` 노티(+AppKit 폴백)로
  창을 연다. `daemon`·`chat`·`nativeEngine`을 팝오버/라벨이 직접 구독해 서버 상태·선택 모델이
  실시간으로 반영되고, 상태 점·문구·툴팁이 현재 전송 경로를 구분한다(서버=`실행 중 · :9379`,
  앱 내 엔진=`준비됨`/`준비 중`/`준비 안 됨`/`실패`). 상단 토글 버튼도 경로를 따라 서버 시작/중지와
  앱 내 엔진 준비/중지를 바꿔 보여준다. 데몬·엔진 상태 변화에 맞춰 버튼 툴팁도
  동기화한다. [macos]

* Exa 비용 절충 + 웹 결과 활용 규칙 (T-354): 검색은 캐시를 그대로 쓰고 `web_fetch`(contents)만
  `maxAgeHours: 0`으로 라이브 크롤해 지연·크레딧을 아낀다. 최신성은 검색 1위 본문 자동 첨부가
  담당한다. 시스템 프롬프트에 `[웹 결과 활용 규칙]`을 추가해 "[1번 페이지 본문]이 있으면 그
  본문으로 바로 답하고, 부족하면 즉시 web_fetch를 호출하며, '확인해 보겠습니다'만 말하고
  끝내지 말 것"을 도구 결과를 받는 턴에도 주입한다. [macos]

* Exa 라이브 크롤 강제 (T-353): Exa 검색·contents 요청에 `maxAgeHours: 0`을 넣어 캐시 대신
  항상 새로 크롤한 본문을 받는다. 기본 캐시가 GitHub 릴리스 페이지를 오래된 버전(v0.16.1)에서
  멈춘 채 반환해 최신 버전(v0.17.1)을 못 읽던 문제 해결. 웹 도구 설명에도 "말로만 예고하지 말고
  즉시 호출" 지침을 보강했다. [macos]

* 웹 검색 wigolo→Exa REST 교체 (T-352): 내장 wigolo 데몬·설치 파이프라인·설정 UI·설치 제안
  배너를 전면 삭제하고, Exa API(`api.exa.ai/search`·`/contents`, Bearer 인증)로 교체했다.
  검색은 `contents.highlights` 기반 발췌(300자 cap), 페이지 가져오기는 text(8K cap). 등록
  게이트는 바이너리 존재→**API 키 존재**로 바뀌어 키가 없으면 웹 도구가 모델에게 전달되지
  않는다. 설정 도구 탭 웹 섹션에 Exa 키 입력(SecureField)+`dashboard.exa.ai` 발급 링크+
  실검색 테스트 버튼을 제공하며, 키는 이 Mac(UserDefaults)에만 저장된다. [macos]
